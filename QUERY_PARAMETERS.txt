CHROVIEWER QUERY PARAMETERS

Values in the URL override locally saved viewer settings for that page load.

LIVE SOURCE
liveSource=ta                 Use TournamentAssistant live replay packets.
playerId=<platform id>        Platform ID whose live play should be watched.
hideUI=true                   Hide all cards, controls, settings, errors, and overlays.
disableGameUI=true            Hide the in-game HUD: health, combo, score, rank, accuracy,
                              multiplier, song progress, and hit-score visualizer.

AUDIO
masterVolume=0..1             Overall output level. Multiplies song and hitsound volume.
songVolume=0..1               Song volume before the master volume is applied.
hitsoundVolume=0..1           Hitsound volume before the master volume is applied.
hitsounds=true|false          Enable or disable hitsounds.
audioOffsetMs=-1000..1000     Shift song and hitsound timing in milliseconds.

For liveSource=ta, masterVolume is re-read while the viewer is running. A same-origin
overlay may update the iframe's query string with history.replaceState and the new
volume is applied without reloading the iframe, map, audio, or renderer.
Example: iframe.contentWindow.history.replaceState(null, '', '?liveSource=ta&playerId=123&masterVolume=0.4')

Cross-origin embeds can update audio without reloading by posting a message to the
viewer iframe:
{ type: 'beatkhana:viewer-settings', masterVolume: 0.4, hitsoundVolume: 0.8 }

REPLAY COMPOSITOR
compositor=replay              Play several TARF replays of one map in a single renderer, driven by the
                              parent page's clock like a video. The parent posts:
  { type: 'beatkhana:replay-compositor-config', version: 1,
    players: [{ id, tarfPath, side, name, avatarUrl?, color?, offsetSeconds?, settings? }],
    layout?: 'auto' | 'columns' | 'rows', focus?: id | null, audio?: id | null,
    volume?: 0..1, hitsoundVolume?: 0..1, showNames?: boolean, disableGameUI?: boolean }
  { type: 'beatkhana:replay-compositor-transport', version: 1, playing, time, rate }
                              Players with the same side share their half of the view: left and right,
                              or top and bottom when each side has three players (layout=auto). focus
                              shows one player full size. Only the audio player is heard (the focused or
                              first one by default). time is in song seconds; send the transport on every
                              play, pause, seek and rate change, tiles keep in step in between. A replay
                              waits on its first or last frame outside its own song.
                              The compositor posts beatkhana:replay-compositor-ready when it can take a
                              config, and beatkhana:replay-compositor-state five times a second:
                              { ready, time, duration, players: [{ id, status, error, time, duration }] }
                              with status loading, ready, playing or error. tarfPath URLs on other sites
                              are fetched directly when they allow it (CORS), otherwise through the proxy.

TA IFRAME SYNCHRONISATION
TA viewers on the same origin announce their platform ID, map hash, available replay
range, and playback clock to one another. Viewers with the same map hash rendezvous at
the earliest time available to every iframe and then correct clock drift automatically.
BroadcastChannel is used when available, with same-origin localStorage events as the
fallback. No parent-page coordinator is required.

LIGHTING AND PERFORMANCE
lights=full|static|none       Full mapped lights, fixed static lights, or no mapped lights.
lightshow=full-lightshow      Show only the full lightshow and hide gameplay objects.
showcase=true                 Hide gameplay notes, bombs, arcs, chains, and interactable walls.
                              Fake or uninteractable decorative walls remain visible.
                              Without showcaseConfig, an ordinary map= source is loaded.
                              With showcaseConfig, the configured showcase owns map loading.
qualityPreset=broadcast       Apply the optimized broadcast defaults listed below.
maxFps=1..240                 Maximum render frame rate. Broadcast default: 60.
graphicsQuality=none|low|medium|high
mirrorQuality=none|low|medium|high
                              Mirror-only alias for graphicsQuality.
mirrorResolution=0..4096      Mirror target size in pixels; 0 disables mirrors.
mirrorMsaaSamples=0..8        Mirror render-target MSAA samples.
msaaSamples=0..8              Main scene render-target MSAA samples.
postBloomWidth=64..2048       Base width of the post-bloom pyramid.
bloomFogSize=64..1024         Width and height of the bloom-fog capture target.
screenDisplacement=true|false Enable wall screen-displacement rendering.
renderScale=0.5..1.5          Internal rendering resolution multiplier.
outputWidth=64..7680          Fixed base output width; requires outputHeight.
outputHeight=64..4320         Fixed base output height; requires outputWidth.

The broadcast preset uses maxFps=60, renderScale=0.85, msaaSamples=2,
mirrorResolution=0, mirrorMsaaSamples=0, postBloomWidth=640,
bloomFogSize=256, screenDisplacement=false, replayTrailSamples=12, and static
lights. Any explicitly supplied setting above overrides the preset. Fixed output
dimensions are multiplied by renderScale and the capped device pixel ratio.

Every saber parameter is validated with the same limits as the settings panel. Flat
parameters override saved settings and may also be supplied inside the existing
settings JSON query object.

Custom sabers retain their native mesh and trail endpoints. CG5 includes its
animated fire trail and glow. In the compositor, set saberModel=cg5 in the selected

&saber=cg5 (or &saberModel=cg5) to that player's URL.

PLAYBACK AND SOURCES
autoplay=true|false           Attempt playback without waiting for the play button.
map=<BeatSaver key or URL>    Load a map preview.
replayUrl=<HTTPS URL>         Load a replay file.
tarfPath=<path or HTTPS URL>  Load a TournamentAssistant (.tarf) replay from a path on this site,
                              like /replays/match.tarf, or from another site. A map baked into
                              the replay is used instead of downloading it from BeatSaver.
bkacrPath=<path or HTTPS URL> Load a BeatKhana anticheat replay (.bkacr): a replay with the anticheat's
                              report. A panel lists the findings; notes they point at are ringed, swings
                              show the path of the saber tip and the timeline marks every place.
bkaccmpPath=<path or HTTPS URL>
                              Load a BeatKhana anticheat comparison (.bkaccmp): several players' replays of
                              one map. The first is played back, the others are drawn as coloured sabers
                              with the same song clock, next to how alike the players move.
t=<seconds>                   Initial song time for non-live playback, in seconds.
scoreId=<ScoreSaber score>    Load a ScoreSaber replay.
beat=<number>                 Initial beat for non-live playback.
difficulty=1|3|5|7|9          Easy, Normal, Hard, Expert, or ExpertPlus map preview.
characteristic=<name>         Map characteristic, for example Standard or OneSaber.

?liveSource=ta&playerId=76561199016011545&hideUI=true&masterVolume=0.8&songVolume=0.7&hitsoundVolume=0.5&lights=static&renderScale=0.75

?showcase=true&lights=full&map=key

MULTIVIEW REPLAY SCORES
A multiview parent may add scores: { rateHz } (1..60) to beatkhana:multiview-config. Each tile's score is
then read from the replay it is drawing, at its own playback time, and posted that many times a second
(only when something changed):
  { type: 'beatkhana:multiview-scores', version: 1,
    players: [{ id, playerId, platformIds, time, score: { scoreWithModifiers, maxScoreWithModifiers,
      accuracy, combo, maxCombo, notesMissed, badCuts, bombHits, wallHits, playerHealth, songPosition } | null }] }
score is null until the tile's playback reaches its replay. TournamentAssistant streams scores with
modifiers applied, so no unmodified score is sent. A stream joined mid-song takes the misses, cuts, hits
and highest combo it did not see from the realtime score the parent sent for that moment.

COMPOSITOR SYNCHRONIZATION
compositorSyncType=slow|wait-for-all
compositorWaitSeconds=1..60   Default 30 seconds, maximum 60 seconds.
All visible players must select wait-for-all. Missing or mixed settings default to slow.
Waiting holds stream playback until the same map hash, difficulty, characteristic and song speed are buffered for every visible player. All clocks are started in one compositor task using a common time reference. A timeout or incompatible map falls back to normal gradual playback. When the wait times out, the players that are ready start together; a player whose stream begins after the others started stays waiting until it has their moment of the song buffered, then joins at that time. While a player who has played this map is paused (or reconnecting, up to the wait time), the other players hold still and show waiting; when it plays again, everyone continues from its time. A stream that began more than ten seconds before the viewer connected (an overlay reloaded mid-song) waits at most three seconds for the other players, and a start packet that delivers no frames for five seconds is shown as waiting rather than preparing. Replay memory is bounded while waiting and while playing the delayed stream.
For multiview embeds these values belong in each player's settings object. Slow mode remains the default. Browser, OBS, windowed and Spout bridges all use the same compositor protocol and render host.
